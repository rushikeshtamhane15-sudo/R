# RCA — Build failure (run 0012fc01-2b35-44ac-a4ae-a875fd641054)

## Outcome
Deploy FAILED at `build_image` (Cloud Build step #2 "docker-build"), in the `frontend-build` stage during `yarn build`. This is an **app source-code fault**, not a deployment/manifest issue. It must be fixed in the frontend source; the deployer cannot patch it via manifests.

## Failure
Cloud Build `frontend-build` stage → `craco build` → "Failed to compile":

```
SyntaxError: /app/src/pages/SuperAdminMesses.jsx: 'return' outside of function. (573:2)
error Command failed with exit code 1.
```

## Root cause
In `frontend/src/pages/SuperAdminMesses.jsx`, the helper component `Field` lost its function declaration line. The main `SuperAdminMesses` component closes at line 572 (`}`), and line 573 begins with an orphaned `return (` that renders `label` / `children` / `hint` — i.e. a `Field` component body with **no `function Field(...) {` header**. Babel therefore sees a `return` at module scope → "'return' outside of function".

`<Field label=... hint=...>` is used ~15 times in this same file (lines 279–333), so the component is required — it just needs its declaration restored.

Original (broken):
```jsx
571:   );
572: }
573:   return (              // <-- orphaned, no function header
574:     <div>
575:       <label ...>{label}</label>
576:       {children && <div className="mt-1">{children}</div>}
577:       {hint && <div className="text-[10px] text-slate-400 mt-1">{hint}</div>}
578:     </div>
579:   );
580: }
```

## Fix (verified in eph sandbox)
Insert the missing function declaration immediately before the orphaned `return (` at line 573:

```jsx
571:   );
572: }
573: function Field({ label, children, hint }) {
574:   return (
575:     <div>
576:       <label ...>{label}</label>
577:       {children && <div className="mt-1">{children}</div>}
578:       {hint && <div className="text-[10px] text-slate-400 mt-1">{hint}</div>}
579:     </div>
580:   );
581: }
```

The destructured props (`label`, `children`, `hint`) match every existing `<Field>` usage in the file.

## Verification
Reproduced and fixed in the eph sandbox using `@babel/parser` (plugins: `jsx`):
- Unfixed file → `'return' outside of function. (573:2)` (exact match to the Cloud Build error).
- After inserting `function Field({ label, children, hint }) {` → `PARSE_OK`.
(Full `yarn install && yarn build` not re-run in-pod — the failure is a pure parse-time syntax error, fully covered by the parser check.)

Apply the one-line fix above to `frontend/src/pages/SuperAdminMesses.jsx` in the source/preview environment, then re-trigger the deploy. No manifest, secret, tier, or DB change is needed.
